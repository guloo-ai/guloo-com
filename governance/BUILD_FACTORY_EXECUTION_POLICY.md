# GULOO 24H Build Factory — Execution Policy V1.0

Status: ACTIVE

## 1. Mission
Continuously convert approved GULOO strategy into small, testable, versioned and auditable enterprise capabilities while protecting people, money, credentials, customer data and brand trust.

## 2. Non-negotiable gates
Every execution must pass:
1. Constitution / mission alignment
2. Permission boundary
3. Risk classification
4. Budget boundary when applicable
5. Data minimization
6. Verification / test
7. Audit trail

## 3. GREEN authority
May execute without chairman interruption when all are true:
- reversible;
- no payment or purchase;
- no credential creation/rotation/disclosure;
- no customer/personnel data mutation;
- no external message or legal commitment;
- no destructive deletion;
- no permission escalation;
- no irreversible production migration.

Examples: documentation, schemas, internal analysis, test creation, draft code, repository audits, public-site QA, SEO metadata drafts, non-secret configuration templates.

## 4. YELLOW authority
May prepare but must stop before irreversible/live effect.
Examples: public copy changes, production workflow behavior, CRM automation, pricing rules, live integration configuration, customer-facing forms.
Required output: review-ready artifact + impact + rollback + verification plan.

## 5. RED authority
Chairman approval required before execution.
Includes payments, contracts, procurement, banking, credentials, access grants, deletion, production customer-data mutation, legal filings, external outbound communication, high-impact security changes.

## 6. Verification rule
No task is DONE merely because a file was written. DONE requires evidence appropriate to the task: test pass, link check, schema validation, diff review, or explicit acceptance criteria.

## 7. Failure rule
On failure:
- stop mutation;
- preserve evidence;
- mark BLOCKED;
- record root cause hypothesis;
- propose smallest safe next action;
- never hide or auto-retry a potentially destructive action.

## 8. Human Flourishing Principle
Automation exists to reduce avoidable cognitive and administrative burden, improve clarity and service, and return human time to judgment, creativity, relationships and care. Efficiency that materially harms people, trust, safety or dignity is not considered success.
